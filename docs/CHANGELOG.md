All notable changes to VibeCody are documented here. This project follows [Semantic Versioning](https://semver.org/).


## [Unreleased]

### Fixed

- **The draw.io panel is a file editor now, not a canvas that forgets.** It had every part of a diagram editor except the file. It opened blank every time with no way to reach a diagram that already existed — the repository's own five `docs/*.drawio` were unreachable from it. Its Save wrote to a hard-coded `<workspace>/diagrams/diagram.drawio`, so **the second diagram you made silently replaced the first**, and the toolbar said *"Saved to workspace"* without ever naming the file; the call behind it was `.catch(() => {})` followed by an unconditional success message, so a failed write reported as a save. It could not export at all. And the embedded editor showed a **Save & Exit** button that saved and then sat there, because the URL passed `noSaveBtn=1` — which replaces draw.io's *Save* with *Save & Exit* — while nothing on this side handled the `exit` event. **A new Diagrams tab lists every `.drawio`, `.dio` and `.drawio.svg` in the workspace**, newest first, with page and shape counts that are *absent* rather than zero when a file was too large to count, and no timestamp at all where the filesystem reported none. Opening one loads it into the editor and Save writes back to **that** file, named in the toolbar at all times with a dot for unsaved changes; a diagram with no name yet asks for one instead of choosing. **Export writes into the workspace** beside the diagram — `docs/architecture.drawio` → `docs/architecture.png` — because draw.io's own export menu downloads through the browser, which the Tauri webview does not surface, so that route produced a file nobody could find. `autosave=1` was missing from the editor URL while this file already had an `autosave` handler, so that branch never ran and Save could write a diagram several edits stale. **The eight templates were eight promises**: every one returned the same single rounded rectangle containing its own name, so picking "Microservices Architecture" gave you one box saying *Microservices Architecture*. They are now real starter diagrams in `drawio_templates.rs`, served from the backend so the tab cannot advertise one this build lacks, with a test asserting each has at least four shapes and three connections and that no edge points at a cell that does not exist. Previewing a `.drawio` from the file tree showed a blank frame: the viewer URL never asked for the embed protocol (`embed=1&proto=json`) and never acknowledged `configure`, so the `init` event the component was waiting for could not arrive. Every path is now workspace-relative and resolved inside the open workspace — `execute_drawio_mcp` took a free-form absolute path, making the diagram bridge a general-purpose read/write primitive for anywhere the deny-list happened not to cover — and an export's `data:` URL is bounded *before* anything is allocated from it. Saving back into a `.drawio.svg` is refused by name rather than half-done, because writing only the embedded XML would leave the picture showing the previous version. New: `vibecoder/src-tauri/src/drawio_templates.rs`.

- **A healthy daemon that rejected every client for two and a half days.** `~/.vibecli/daemon.token` names no port, and the daemon runs on any port — so every daemon on the machine wrote the same file and the last writer won regardless of which one was still alive. On 1 September a daemon bound port 7979, wrote that file, and exited two minutes later on `SIGTERM`. The daemon on 7878 stayed up, answered `/health` perfectly, and returned **401 to everything else** until it was restarted. What the user saw was *"Could not read speech settings from the daemon (daemon returned 401). Is it running?"* — a question whose answer was yes, pointing at the one thing that was not the problem. `serve.rs` had already been taught to bind before writing the token, but that only covers a *same-port* daemon losing the race; the 7979 daemon lost nothing, it bound a free port and wrote a file it had every reason to think was its own. **The file is now named after the port** — `daemon-<port>.token` — and the shared `daemon.token` is written only by the daemon on the port clients resolve by default, so two daemons cannot collide; it is removed again on clean shutdown, because a token file that outlives its daemon is not a stale cache but a wrong answer with the shape of a right one. **The layout has exactly one implementation**, the new `vibe-daemon-token` crate, replacing seventeen private copies of the same path join across the daemon, three Tauri shells, the eval harness, the TUI, the `vibecli-mistralrs` provider, the Agent SDK, the VS Code extension and the JetBrains plugin — a crate of its own because `vibe-eval` is depended on *by* `vibecli` and could not depend back. **And a 401 is no longer reported as a diagnosis it is not.** `/health` publishes `api_token.fingerprint`, a SHA-256 prefix that reveals nothing about a 128-bit CSPRNG secret, so a client can compare what it holds against what the daemon accepts *before* issuing a request: `Valid`, `Stale`, `Missing`, or `Unverifiable` for a daemon too old to say — four states with different fixes, where `stale` needs the daemon restarted and `missing` needs it started. `daemon_bootstrap::ensure_ready` checks the process **and** the credential **and** the version together, because `ensure_running` alone answered `true` throughout the whole outage; all three shells expose it as `daemon_readiness` and `daemon_readiness_probe` (which never starts a daemon — a poll must not resurrect one the user stopped), and `useDaemonMonitor` now says so once per episode rather than every thirty seconds. A route answering **404** from a correct panel is named as what it usually is: an installed daemon older than the app. The three partial copies of `daemonFetch` in `vibe-ui-shared` — none of which retried a 401, so a daemon restart left speech settings and the harness panel broken until the app was relaunched — are now one shared helper that VibeCoder re-exports. New: `crates/vibe-daemon-token`, `packages/vibe-ui-shared/src/lib/daemonFetch.ts`. See [Key rotation](/vibecody/security/key-rotation/).

### Added

- **Developer Excellence: DORA and practice maturity, measured from the repository.** VibeCoder could grade a service's delivery performance before this, and the grade was a constant. `evaluate_idp_scorecard` awarded every registered service 8/10 for deploy frequency, 7/10 for lead time, 6/10 for MTTR and 5/5 for change failure rate, under a comment reading *"simulated DORA-style metrics (would connect to real CI/CD in production)"* — 35 of the scorecard's 100 points, on screen, in a panel a director would read as a measurement. The four keys are now **computed from git history**, and every number states where it came from: `vibecli --devex dora` reports each key with its band, its sample size, and the **proxy** it was derived from, because nothing in a repository knows what "production" means and a DORA number whose proxy is unstated cannot be argued with. **Absence is the feature.** A repository whose deploys are not tagged does not get `0.0 deploys/week` — zero is a claim about their delivery, absence is a claim about your instrumentation, and only one of them is true. It gets `deployment_frequency: unmeasured` with the reason spelled out and the concrete change that would fix it, and the panel renders that block as prominently as the values. `fix:` commits are deliberately **not** counted as remediation: most of them fix a bug found in development, and counting them would push change failure rate toward 100% for every healthy team. Practice maturity scans ten practices at the workspace root and **never reports level 4** — a file proves a practice is present, not that it is followed, reviewed or improving, so the top level stays attested by people rather than earnable with `touch`; where path detection is known to under-report (Rust `#[cfg(test)]` tests have no `tests/` directory; a monorepo's lint config lives one level down) the practice carries a `detection_caveat` printed beside the misses, not in a footnote. Onboarding reports bootstrap readiness and first-time contributors, and **refuses to report time-to-first-commit**: git records a contributor's first commit but not the day they joined, so the interval the day-one target is about has no start, and any number there would have invented one. `vibecli --devex gate` fails a pipeline on a missed band with exit `1` and on an **unmeasurable** required metric with exit `3` — kept apart because a pipeline that conflates them either blocks releases for a tooling gap or ships on an absence — and a gate with no `--require-*` threshold is refused outright, so the cheapest route to green is never to delete the criteria. **SPACE is the same discipline applied to the half DORA cannot see.** Most of SPACE is not in a git repository, and `--devex space` reports the *frame* rather than approximating it: Performance is carried by reference from DORA's stability pair so it is never double counted, Activity is commits/authors/deployments as counts and never names, Collaboration gets the one thing git genuinely sees — files touched by more than one author, and the recorded `Co-authored-by` share — and Satisfaction, Efficiency and **review latency** are returned as named gaps pointing at the survey, at CI, and at the forge's pull-request API. Review latency is deliberately absent rather than derived from merge timestamps: a merge commit records when a branch landed, not when anyone first looked at it, and reporting the one as the other would publish queueing time as review time. Two rules are enforced in the shape of the data instead of left to the reader — **there is no aggregate SPACE score** (a test asserts the payload carries no `score`/`total`/`overall` field, because a number summing a survey response with a commit count cannot be wrong and therefore cannot be useful), and **volume is never reported without an outcome signal** (`outcome_signal` is false when Performance has no measure, and the panel renders that as an alert; a single-author window also gets no multi-author file share, because with one author it is 0 by arithmetic rather than by how the team works). Nothing in the report is per-individual: author counts are activity, author names would be surveillance, and the shape has no field for them. `--devex survey` prints the quarterly instrument, carrying the anonymity and no-performance-review commitments in the document itself. Ten new skills in the `devex` category (eleven counting the existing `devex-developer-experience.md`), routed by `devex-director-operating-system.md`, and six slash commands (`/devex`, `/dora`, `/space`, `/practices`, `/onboarding`, `/devex-plan`) that cite their skill file **with the extension** — `get_skill` now accepts either spelling, so a name copied off the page in front of you resolves instead of returning `not found`. New: `vibecli/vibecli-cli/src/devex_metrics.rs`, `devex_routes.rs`, `devex_cmd.rs`; panel Cloud & Platform → Developer Excellence, with Delivery, Experience, Practices and Onboarding tabs. See [Developer Excellence](/vibecody/developer-excellence/).

- **The Observe-Act loop actually runs.** VibeCoder's Observe-Act panel had every control a computer-use agent needs and drove nothing: **Start** set a local string to `"running"`, the Monitor tab said *Capturing…* over a grey rectangle forever, and **Save Config** wrote a file under the project data directory that no code path ever read. The pieces existed on either side of a missing middle — `observe_act.rs` had the action enum, the session state machine and the safety rails; `desktop_agent.rs` had the mouse, keyboard and screenshot commands — with nothing joining them, no route to reach them, and `/v1/capabilities` advertising the feature to every client. The loop is now real: screenshot → vision model → validate → act → verify → repeat, in the daemon, behind `/observe/*`. **Coordinates were the hard part.** Three spaces are in play — the downscaled image the model actually sees, the capture file's pixels (2× the screen on Retina), and the points `cliclick` takes — and the daemon measures image width against logical width and divides, rather than inferring the backing scale from whether `system_profiler` prints the word "Retina", which is absent on a scaled resolution and wrong on a second display. Coordinates are mapped **before** the rails run, so a forbidden region is checked against the pixel the click will reach, not the one the model named. **The three safety modes are enforced and tested**: Restricted executes nothing and records what it would have done (struck through in History, so a read-only run is not indistinguishable from a run that did nothing); Cautious stops on a destructive action and treats five minutes of silence as a **refusal**, because an operator who walked away has not approved anything; Autonomous asks nothing. An over-long action batch is refused whole rather than truncated, and a `wait` is clamped to 30 s, a `type` to 4096 characters, a `scroll` to 50 — each of them a way one model turn could otherwise park the session with nothing on screen saying why. **A step is verified, failed, or unverified — three states, not two.** The old panel modelled it as `verified: boolean`, which rendered "we did not check" as **Failed**; an unverified step now leaves the failure streak where it was and stays out of the rate's denominator, so a run with verification off reads `n/a` rather than 0%. Two sessions cannot run at once (409): two loops moving one mouse each verify against the other's half-finished work. A session interrupted by a daemon restart reloads as **aborted**, not as a running phantom no stop button can clear. `screencapture` exiting 0 with Screen Recording denied — the one failure that looks like success — is caught by checking the file exists and named as the permission it is, and the panel's preflight names a missing `cliclick` with the `brew` line to fix it. Provider-agnostic and strictly so: `provider` and `model` are required on `POST /observe/sessions` with no fallback to the daemon's boot provider, because a silent fallback would send screenshots of the user's desktop to a vendor they did not pick. Twenty-two runtime tests drive the whole loop through a recording fake, so the rails are checked without a display or an API key. New: `vibecli/vibecli-cli/src/observe_act_runtime.rs`. See [Observe-Act](/vibecody/observe-act/).

- **Archives open in the file explorer.** A `.zip`, `.jar`, `.vsix`, `.apk`, `.tar.gz`, `.tar.zst` — fifteen ZIP-container extensions, tar, and four compressors (gzip, bzip2, zstd, xz) — expands in VibeCoder's tree the way a folder does, and anything inside opens read-only in Monaco with highlighting, search, and image/PDF rendering. **Trying to edit is the interesting part**: rather than the silent no-op Monaco gives a read-only model, the keystroke (or ⌘S, or the context menu) offers to extract the whole archive into a sibling folder named after it — `dist.tar.gz` → `dist/` — and reopens your file from there, writable, with its neighbours intact so relative imports still resolve. The prompt names the exact folder *before* anything is written, including the `-1` suffix when a previous extraction is still sitting there, because silently merging into it is how someone loses the edits they made last time. The archive itself is never rewritten: VibeCody does edit DOCX and EPUB containers in place, and does it by copying every untouched entry back byte for byte in its original order with its original compression method — generalising that to a signed `.apk` is not a promise worth making. DOCX, XLSX, EPUB and friends are deliberately *not* treated as archives; they already have a viewer. **Nothing allocates from a declared size** — a member can claim 8 GiB it does not have, and 40 KiB of zip can expand to a terabyte, so every bound (64 MiB per member, 2 GiB per extraction, 200 000 entries) is enforced by reading, zip-slip paths are skipped rather than written, and a failed extraction deletes its half-built folder instead of leaving it. A tarball has no central directory, so its listing is cached per (path, mtime, size) — without that, expanding five folders in a `.tar.gz` decompressed it five times. See [archives.md](/vibecody/archives/).

- **PDFs open as text, and save back.** A `.pdf` gains the same **Edit text** button DOCX, EPUB and Pages have. A PDF has no paragraphs — it has glyphs at coordinates — so it opens as plain text, one line per line of the page, one section per page, and the words on a line can be changed or the line cleared. Everything a PDF cannot do is an error naming what it is rather than a guess: **a line cannot be added** (a new line has no position, no font and no place in the content stream), a character the font cannot draw stops the save and is named, a page marker cannot be dropped, an encrypted file says so and asks for an unprotected copy, and a page drawing an inline image is left alone because pixels written between `BI` and `EI` do not survive the stream being rebuilt. **A change goes back to the run that drew it**, encoded through that run's font — every font in a modern PDF is subset to the glyphs its own words used, so a sentence with one bold word has no single font that can draw the whole line; measured on 500 PDFs, writing the line through the first font alone failed on about one line in ten that this deals back correctly. **What a font's codes mean is read, never assumed**: a `/ToUnicode` map first, then a named base encoding, then `/Differences`; where none of them answers — a symbolic font, a composite font with no map — the run is left out of the buffer and a warning names the font, because a reader that invents characters is worse than one that admits a gap. Words that TeX sets apart by moving the pen rather than drawing a space read as spaces and are written back as gaps. The changed page is **appended as an incremental update**, so the original bytes stay exactly where they are and a packed file comes out the same size — rebuilding one costs up to 70% more. Measured over a random 500 of every PDF on one machine: of the 285 with an editable line of text, **271 took an edit, saved, and read it back**; 14 were refused by name because no font on the line carries the character asked for; the rest are system vector assets with no text, files that are not PDFs, or one encrypted. New: `crates/vibe-docfmt/src/pdf/`.

- **Two pages side by side.** **Two up** in the document toolbar puts a PDF into a real spread — facing pages, *Pages 7–8 of 120* in the toolbar, ← and → turning a whole spread — and a DOCX or an EPUB chapter into two columns of a screen, paged sideways. The two are different on purpose: a PDF has pages and a chapter does not, so one counts pages and the other counts screens rather than pretending a reflowable document has sheets. Switching layouts keeps you on the page you were reading (page 8 one-up becomes the spread 7–8, not 8–9), an odd-length document ends on a single page rather than a blank one, and the choice is remembered per document for the session. Pages open **fitted to the window** rather than at 100%, which for a spread is two half-pages. **PDF pages are now drawn by the app** rather than handed to the platform's viewer inside an `<iframe>`, which is why that panel had no page navigation and no spread — everything inside that frame belonged to the browser. The renderer is imported the first time a PDF is opened, so the startup bundle is **138 kB gzipped smaller** than importing it with the viewer would have made it. The columns are laid out with a gap of exactly twice the margin — not a taste decision: any narrower and the next screen's first column shows through the pane's padding, permanently, as a sliver of the following page.

- **Mermaid and PlantUML diagrams are drawn, in markdown and on their own.** A ```` ```mermaid ```` or ```` ```plantuml ```` block in a markdown preview becomes the diagram; a `.mmd`, `.mermaid`, `.puml`, `.plantuml`, `.wsd` or `.iuml` file opens as the picture, with **Source** to go back to the text and the preview following the buffer as you type. Mermaid is bundled and drawn in the app — the Diagram Generator's existing preview imported it from jsdelivr inside a sandboxed iframe, which the app's own CSP (`script-src 'self' blob:`) blocks, so that pane could never draw anything on any machine, online or off; it now uses the same renderer as everything else. **PlantUML is a Java program with no browser port**, so it is run locally (`-pipe`, nothing written to disk) and *nothing is sent to a remote renderer* — the usual trick of encoding the source into a plantuml.com URL is someone else's server reading your architecture because a picture appeared. With no PlantUML installed the diagram says so and how to install it. `-failfast2` is passed deliberately: without it PlantUML renders a *picture of* a syntax error and exits 0, which is a failure reported as a drawing that worked. Two things a diagram will never do: render blank, or render something the file could script — a failed diagram shows the renderer's own message **and the source that produced it**, and every SVG is sanitised before it reaches the DOM. Mermaid's labels are configured as SVG text rather than HTML in a `<foreignObject>`, because the sanitiser removes that namespace wholesale: the first working build drew every box and arrow with **not one label**, which looks like success. Mermaid loads on first use, so the startup bundle grows by 5 kB rather than a megabyte.

### Fixed

- **The IDP scorecard reported delivery performance it had never measured.** Four of Cloud & Platform → IDP's nine metrics — Deploy Frequency, Lead Time for Changes, Mean Time to Recovery, Change Failure Rate — were hard-coded integers contributing 35 of a 100-point grade, so every service ever registered scored identically on all four regardless of how it was actually built or shipped. They are **removed rather than replaced**: a catalog entry holds a `repo_url`, not a checkout, and DORA needs history, so there is nothing this function could honestly compute. The denominator drops to 65 with them, so the percentage still means "of what was assessed"; the response gained a `scope` line saying the grade covers catalog metadata only and an `unmeasured` block naming the four keys, why they are absent, and where they *are* measured; and the panel renders both, because a client that dropped them would put the same grade back on screen looking like a whole-service score. The recommendation *"Improve DORA metrics by automating deployments and reducing batch sizes"*, which fired below 80% on the strength of those constants, is gone too — a function that measures none of the four keys is in no position to tell anyone their batches are too large.

- **The TLS inspector called every certificate invalid.** Network Tools → TLS reported *Invalid / Expired* and *0d remaining* for every site on the internet, github.com included — directly above its own raw output showing the chain verifying at every depth. The dates were being read out of `openssl s_client`'s human-readable chain listing, where OpenSSL 3 prints `v:NotBefore: …; NotAfter: …` and OpenSSL 1 printed no validity dates at all; the parser looked for `Not After`, with a space, found nothing, and rendered *no expiry date* as **zero days left, and therefore expired**. The fields now come from `openssl x509 -noout -subject -issuer -dates -serial -ext subjectAltName`, one documented `key=value` per line on every version — which also brings back the serial number and the SAN list, empty until now for the same reason. Days remaining is counted on a real calendar instead of `(year - 1969) / 4` and a fixed table of month lengths, so a leap year is not a day out, and it is **absent when the date could not be read** rather than zero, because absent is not expired. The verdict stopped being a boolean: *Expired*, *Not yet valid*, *Chain not trusted — self-signed certificate* and *Could not read the certificate* are four different things, and reporting all four as "Invalid / Expired" is what let a parsing bug look like a bad certificate. The verify result is also read from stdout, where openssl prints the line that states the outcome, rather than stderr, which carries only the reassuring `verify return:1` callbacks. Checked against the live internet (`cargo test -p vibe-coder -- --ignored tls_inspector`): github.com valid with 88 days left, `expired.badssl.com` expired 4160 days ago, `self-signed.badssl.com` untrusted with its dates still readable, and a closed port an error naming the port instead of an empty certificate. New: `vibecoder/src-tauri/src/tls_cert.rs`.

- **A release build made with cargo alone opened on a blank window.** The frontend is compiled into the binary only when the `tauri/custom-protocol` feature is on — `tauri build` passes it, `cargo build --release` does not — and without it the window is pointed at `http://localhost:1420` instead. With no dev server running that is a white rectangle and *nothing else*: no panic, no log line, no failed request anyone sees. Every shipped build was fine, because CI and `make build-*` both go through `tauri build`; the trap was only there for anyone reaching for cargo directly, and it cost an afternoon to find. All three shells now declare the `custom-protocol` feature, so `cargo build --release --features custom-protocol` embeds properly (**412 asset keys in the binary**, against 0 before), and the build says so twice when it will not: a `cargo:warning` at build time naming the fix, and a line on stderr when such a binary starts. The feature is deliberately not a default — embedding brotli-compresses the whole bundle during macro expansion, and `cargo check` would otherwise pay for it on every run.

- **Word documents could be opened but not saved.** Every real `.docx` tried — a résumé, two book manuscripts — failed verification and refused to write, which is the crate working as designed but is not a feature. The buffer and its own parse disagreed in six ways, each of them a place where the Markdown writer produced text the Markdown reader read back as something else: a trailing non-breaking space (Word ends paragraphs with them constantly, and `str::trim` eats U+00A0 because Unicode calls it whitespace); an ASCII diagram's leading indentation; a hand-numbered paragraph — "2. Map your first 90 days" typed into Word — read back as the *second item of a list* and renumbered to "1."; `**bold ****bold italic***` emphasis, whose markers merge into an ambiguous `****` that no parser recovers; a code run containing a backtick, closing its own fence early; and a link whose `href` arrived with the newline XHTML wraps long attributes at, splitting the buffer line in two. Emphasis is now *factored* (`**bold *and italic* more**`), code runs get a fence longer than their own backticks, a paragraph that opens like a heading, bullet, table row or numbered item is escaped, and every scanner steps over a whole code span or link rather than reading the `*`, `_` or `]` inside it as markup. **Measured, not asserted**: every `.docx` and `.epub` file on one machine — 434 of them — now round-trips and verifies, and 427 of the 430 that have an editable line took an edit and read it back (the other three could not be copied), against 11 that could not be saved before — and the same fixes repaired five e-books, including one whose fenced code block contained a ``` line and one whose blank line inside a code sample was being eaten by the list-spacing pass.

## [0.5.11] - 2026-08-28

### Added

- **Re-run Review, from the findings.** The control that starts a review lives on the Changes tab, so re-reviewing after an edit meant leaving the report to go and find it. The button now sits on the report itself and repeats the run with the **same base ref** — a test pins that by comparing the second call's arguments to the first's, because a re-run that quietly reviews something else is worse than no button.
- **A model of its own for spoken replies.** **Settings → Voice** now carries the model that answers a voice turn, separately from the model the composer is set to for writing code (`[voice] provider` / `[voice] model`, over `PUT /voice/settings`). The two jobs have different budgets, and the model is nearly the entire spoken one: measured on a 24 GB Mac against a 20B local model with a README and 400 file paths in the system prompt (4.0k tokens), the model took **5.0 s** warm and **42.0 s** cold — 26.6 s of load, 12.0 s of prefill — against **0.58 s** to recognise the speech and milliseconds to say the reply. Ollama evicts an idle model after about five minutes, so the cold number is not a first-run cost, it is what the first turn after a pause costs. Set, the pair wins over what the client sends, because a setting that deferred to the client would be visible, saved, and inert on all three desktop shells; unset, nothing changes. Both halves or neither — given one, the daemon builds no override and silently uses its own provider, so half a pair is refused rather than stored. The `ready` event now names the model that will actually answer.
- **[Sizing & Hardware](/vibecody/sizing/)** — a new page answering what the documentation never did: how much RAM, disk and GPU each part actually needs, VRAM by model size and quantisation, which workloads use a GPU at all (local inference, and essentially nothing else), and what `vibecli --setup` already decides for you from RAM alone. Measured numbers and estimates are labelled separately throughout, because most sizing advice is arithmetic wearing a lab coat.
- **[Third-Party Services](/vibecody/services/)** — every external service VibeCody can talk to, what each needs from you, and the point the docs had buried: **none of them is required**. One provider key, or Ollama on the machine, and nothing else.
- **The speech engine is configurable, installed, and warm.** **Settings → Voice** in all three shells — engine, language and voice, backed by `GET`/`PUT /voice/settings`. Three things, one of which is the reason none of the rest had ever run. **Nothing built or installed the speech sidecar**: for the whole life of this feature the only reference to building it was a hint string in a prototype's error message, so `tts_sidecar` was unset on every real machine, `Tts::open` fell straight through to batch, and every spoken reply came from one `say` process per utterance in the system default voice — the slowest path and the least natural voice. The engine work was inert and the symptom was "the assistant sounds mechanical". `make voice-sidecar` builds and installs it, `make voice-kokoro` sets up the neural one, and `make voice-status` answers the question that previously had no answer, which is *which engine will actually run*. `Tts::open` also discovers a sidecar beside the daemon binary, so an install needs no config file at all. **Warm at daemon start, not at socket open**: the neural engine measured 6.6 s to load its model and speak its first sample, and paid inside the WebSocket handler that is 6.6 s of silence that looks exactly like a microphone that does not work — one engine is parked at boot, only when voice is configured, and a second concurrent conversation opens its own rather than sharing, since one synthesiser between two sessions would let a barge-in in one cancel the other's speech. Each engine row carries whether it is available **and why not**, because a greyed-out option with no reason reads as a bug; selecting an engine writes its sidecar paths too, because `"kokoro"` with no interpreter configured is a setting that reads back correctly and does nothing. The settings live in the daemon rather than in each app: the daemon is what speaks, and three local copies would be three settings disagreeing about one machine. Voices come from the engine (`--voices`, 28 across 9 languages) rather than a table that is wrong the moment someone installs a language pack, and are grouped by language in the picker because a voice belongs to one. See [Full-duplex voice](/vibecody/voice-duplex/#choosing-a-voice-engine).
- **A neural voice, for anyone who wants one.** `[voice] tts_engine = "kokoro"` runs Kokoro-82M through MLX instead of the platform synthesiser — 54 voices, Apache-2.0, Apple Silicon. It is **not** the default and it is not free: the platform engine reaches first audio in 21 ms and this one in 165–230 ms, both measured by `tools/tts-bench` rather than estimated. The sidecar speaks the same wire protocol as the macOS one, so the daemon needed no new plumbing — point `tts_sidecar` at an interpreter and `tts_sidecar_args` at the script. **On macOS, try the free thing first:** Apple's Enhanced and Premium voices are neural, cost nothing at synthesis time, and are separate downloads most Macs have never made — a machine with none installed speaks in the compact tier, which is what "sounds mechanical" usually means.
- **Audio frames carry their own sample rate.** `AVSpeechSynthesizer` produces 22.05 kHz and Kokoro 24 kHz, and the reader assumed 22.05 kHz for everything. A wrong rate does not fail — it plays the whole reply at the wrong pitch and speed, which sounds like a bad voice rather than a bug. The new `AUR` frame prefixes a `u32` rate; the old `AUD` frame is still read as 22.05 kHz so a daemon can drive a sidecar built before this existed.

- **Every model gets its own context budget, read from the provider.** The agent loop pruned conversation history at 200 000 tokens for every model on every provider, and the chat panel compacted at a flat 80 000 characters — neither number had anything to do with the model in front of you. Both directions were silent: a larger window lost history it never needed to, a smaller one overflowed and the provider dealt with it quietly. Ollama drops the *front* of an oversized prompt, taking the system prompt and the tool contract with it, so the symptom was a model that appeared to forget how to call tools and started emitting malformed markup. Windows now come from the vendor — `context_window` / `context_length` / `max_context_length` / `max_model_len` on an OpenAI-compatible `/models`, `model_info` on Ollama's `/api/show`, `inputTokenLimit` on Gemini. **There is deliberately no table of numbers**: a hardcoded window per model id is a fact about someone else's product, written from memory, wrong the moment a vendor ships a revision. Anthropic and OpenAI publish no such field, so they keep the documented default rather than a guess.
- **Source Control is four tabs.** Review and Tools own the panel instead of stacking as collapsible sections under the changes list, where opening a review meant scrolling past the working tree to read it and back to act on it. Tools gathers the four things that are neither the working tree nor a review of it: AI branch names, AI merge-conflict resolution, changelog generation and the repository's settings. Starting a review stays with the changes being reviewed — the control is on Changes, the findings on Review, and pressing Run switches you there.
- **Full-duplex voice.** The microphone stays open while the assistant speaks, so you can interrupt it mid-sentence and it stops. Push-to-talk stays — it is the right control for dictating a long prompt, and the only one that works without echo cancellation. The pipeline lives in the daemon (`voice_duplex.rs`, `GET /ws/voice/duplex`): voice-activity detection, turn-taking, transcription, the model call and speech synthesis happen in one place, so a client contributes a microphone and speakers and nothing else. Wired into VibeCoder, VibeDesk and VibeAIChat through one shared hook. Measured end of speech to first audio: **134–158 ms** — the first build measured 1076 ms, of which whole-utterance Whisper was 978 ms, and the win was not a faster model but overlapping recognition with the speech so end of turn only has to finalise. See [voice-duplex.md](/vibecody/voice-duplex/).
- **Any language you speak in.** `language=auto` identifies the language each turn across 99 of them, instructs the reply into it, and picks a voice that speaks it. Detection runs **every** turn rather than being pinned after the first: forcing a language suppresses the engine's detection result, so a user who says one Hindi sentence and then an English one got the English turn labelled Hindi and answered in Hindi. Code-switching is the normal case for multilingual speakers, not an edge case.
- **Full-duplex voice is off until you turn it on.** It holds the microphone open for the whole session, so it is disabled by default and the chat window carries the switch: one click enables the feature, a second starts listening, and an **×** turns it back off — closing the microphone rather than just hiding the control that was holding it open. The preference is shared across the three shells, and the hook enforces it as well as the button, because hiding a control is not the same as refusing to open a device.
- **`tools/webview-probe`** — measures the voice stack on the webview engine each platform actually ships (WKWebView, WebView2, WebKitGTK) rather than on a browser standing in for them. The transport arm needs no audio hardware and runs in CI on all three OSes; the echo-cancellation arm needs a real microphone and speaker in one room and stays manual.

### Fixed

- **Switching chats in VibeDesk killed the voice conversation, silently.** The conversation pane is remounted on every chat switch and replaced outright by every full-screen overlay, and the voice session was mounted inside it: its teardown closed the WebSocket and the microphone, and the daemon's history — which lives on that socket — went with them. Clicking a chat, or opening Settings, ended a spoken conversation mid-sentence with no message and left the button offering to start a new one. The session now lives in the shell above that line (`useVoiceSession`), and the pane registers itself as the place completed turns are written; the composer's run controls were lifted out for exactly this reason and the microphone was left behind.
- **An interrupted spoken turn was on your screen and absent from the assistant's memory.** Barge-in is the point of an open microphone, and every abandoned turn returned before recording anything — while the transcript had already been sent to the client and drawn. The conversation history was therefore emptiest exactly when the user had been talking most, and the assistant answered follow-ups with no idea what it had just been asked. A turn the user heard part of is now remembered with what was actually said; a turn superseded *before* any audio went out is carried into the next one, which was already the rule for words interrupted during recognition and is now the rule for words interrupted mid-generation too.
- **A neural voice that cannot speak your language produced silence, and said so in a footnote.** A Kokoro voice belongs to exactly one language — `hf_alpha` is Hindi — and asked for an English sentence it returns no audio at all. The daemon noticed and emitted a `notice`; the reply still arrived as text, was written into the chat, and was never said aloud. Every turn, for as long as that voice stayed selected, which from where the user sits is a microphone that does not work. The sentence is now spoken with the platform voice, which every machine has, and the notice says what happened and how to fix it properly. Measured before and after on the same reply: 0 KB of audio, then 44 KB.
- **VibeDesk picked a default model this machine cannot load.** The picker chose the first row whose name did not contain "cloud" — on a 24 GB Mac, a 19.8 GB model, which Ollama refuses with `model requires 19.7 GiB but only 17.3 GiB are available`. That is an HTTP 500, and 500 is not in the retry classifier, so every run and every spoken turn failed on a model nobody had chosen. `GET /models` now reports each installed Ollama model's size and, where the daemon can state a real budget, that a model exceeds it; the picker skips those when choosing for you and marks them in the menu with the two numbers. macOS only, and by design: on unified memory Metal offers ~75% of RAM as its working set, which is the bound Ollama checks and which reproduces the refusal above to within 1%. Elsewhere the daemon says nothing rather than inventing a bound — a wrong "fits" is worse than no answer. Models over the budget are marked, never hidden or disabled: the limit is raisable, and this is one number about one machine.
- **Every `PUT` and `DELETE` route in the daemon was unreachable from every browser client.** The CORS layer allowed `GET`, `POST`, `PATCH` and `OPTIONS`, and the router serves three `PUT` routes and fifteen `DELETE` ones. A method missing from `access-control-allow-methods` is not a locked door, it is an invisible one: the browser refuses the preflight *before sending anything*, so the caller never gets a status code to explain — it gets the transport error, which in WKWebView reads `Load failed`. The visible symptom was the new Voice settings tab, which could read its settings and never save one. Not a permissions change: these routes were always meant to be callable, and `require_auth` is what decides who may call them. A test now asserts every method the router serves appears in the preflight answer.
- **A failed save no longer erases the Voice settings pane.** The section returned early on `error`, and `error` is set by a failed *save* as well as a failed load — so one blocked request replaced every control with a line of text, and a save problem read as a load problem with nothing left on screen to retry from. The message now sits above the controls; only a load that produced nothing shows on its own.
- **VibeCoder had no Voice settings page at all.** It does not use the shared `SettingsView` — it has an older sidebar of its own — so a section defined privately inside `SettingsView` reached two shells of three and the third silently had none. `VoiceSection` is its own exported module now and VibeCoder's sidebar renders it. This is the same shape as the voice stylesheet VibeCoder never imported: shared code only reaches the shells that ask for it, and `tsc` has nothing to say about a shell that does not.
- **`daemon_port` was never registered as a Tauri command in any of the three shells.** The shared voice hooks (`useVoiceSettings`, `useVoiceDuplex`) ask the host for the port and fall back to 7878 when the call fails, so the fallback ran every time and the failure was invisible on a default machine — and silently wrong on one where `VIBECLI_DAEMON_PORT` had moved it.
- **A question asked in Hindi is answered in Hindi again.** All three shells sent `language: "en"` to the voice socket, and pinning a language does not merely bias the recogniser — it *suppresses* its detection result. Every turn therefore arrived labelled English, the reply-language rule never fired, and the assistant answered in correct, fluent, wrong-language English. They now send `auto`, which detects per turn, because code-switching mid-conversation is normal for multilingual speakers rather than an edge case.
- **The voice follows the language, not the session.** The detected language reached the system prompt but never reached the speech engine, so a Hindi reply was read by an English voice — which is not accented Hindi, it is the wrong sounds. Language now travels with every spoken sentence, including the spoken approval question, and a pinned voice is honoured only while it still matches what is being spoken. Kokoro covers nine languages against the recogniser's 99; when it has no voice, the daemon notices that a speakable sentence produced no audio and says which language it was, rather than leaving a silence that is indistinguishable from a broken microphone.

- **"Can you open that file" now opens it.** The assistant read the file, described it, and the editor never moved — every half worked and there was no join. Three gaps stacked: the daemon's spoken tool vocabulary was `read_file`/`list_directory`/`search_files`/`write_file`/`apply_patch`, all executed against disk with nothing that acts on a window; `useVoiceDuplex` had no channel back into the host beyond `onTurn`, which carries a role and a string; and in VibeCoder `onOpenFile` was threaded to nine panels and stopped at `PanelHost` for the one that hosts the conversation. There is now an `open_file` tool the daemon deliberately cannot execute — it resolves the path, confirms the file exists inside the workspace, and sends the client `{"type":"ui","action":"open_file",…}` to act on. **Opening is not reading, and the prompt has to say so**: asked to "open the config" a model reaches for `read_file` and describes what it found, which is an answer to a question nobody asked. **The client declares whether it has an editor** — VibeDesk and VibeAIChat run the same hook against the same daemon and have nowhere to put a file, so the tool is only advertised to a client that said it can honour it, and that declaration is derived from the presence of an `onOpenFile` handler rather than configured beside it, because two switches for one fact drift into an assistant that says "I've opened that for you" over an editor that did not move. **The path is checked here, not trusted**: "open my ssh key" is a sentence a microphone can pick up, so it is canonicalised and required to name an existing file under the workspace root, and a path that fails is reported to the model as *not* opened. A source-scan test walks the whole prop chain, since every link is an optional prop and `tsc` is happy with a feature that is simply inert.

- **The voice assistant could not use a single one of the tools it was given.** Asking it to open a file in a folder returned "the model produced only reasoning or tool calls and never answered" — for a model that had done exactly what it was told. Two independent defects, either of which was enough on its own. `StreamFilter` suppresses `<think>`, `<thinking>` **and** `<tool_call>`, which is correct for the agent console (it renders tool use as its own structured line) and fatal for a turn that has to *run* the call: the filter sits upstream of the tool gate, so every call was swallowed before the gate could see it, `tool_text()` was always `None`, and no tool ever ran. It now has a `reasoning_only()` mode that passes tool markup through — keeping it out of the speaker is the gate's job, which is what the gate exists for. And the spoken tool contract advertised `list_dir`, a name `parse_tool_calls` has never known; the canonical name is `list_directory`, so following the instructions produced a call that parsed to zero calls. A prompt is an interface: the examples in the contract are now parsed by a test, so the specification is checked against the implementation that has to honour it. The `voice_duplex` test helper that claimed to be "the pipeline the daemon runs" modelled two of its three stages and passed throughout — it now runs all three.

- **VibeAIChat's menu-bar icon is the VibeCody mark, not a white square — and the window has a close button.** macOS draws a template image from its alpha channel alone and discards the colours, so the tray was pointed at the full app icon — 96% of which is opaque — and rendered as a filled block beside Claude's and OpenAI's glyphs. The tray now uses a dedicated template icon (`icons/tray-template.png`): the brand V on transparency, which takes the menu bar's own colour in light and dark. Windows and Linux keep the full-colour icon, since `iconAsTemplate` is macOS-only and a monochrome black glyph would disappear into a dark taskbar. A unit test pins the replacement's shape, because a template icon that covers its canvas fails silently — it looks like a deliberate square. The window is frameless, so its only exits were the — that hides it to the tray and the tray menu's Quit; a ✕ now sits beside the — and quits outright.

- **VibeCoder was rendering the voice controls with no stylesheet at all.** VibeDesk loads `@vibe/shared/voice/voice.css` from `main.tsx` and VibeAIChat from `App.tsx`; VibeCoder never imported it, so the mic button, the full-duplex control and its state dot appeared as bare unstyled markup beside a toolbar of styled ones — for the whole life of the feature. The stylesheet itself was correct and fully themed, which is why nothing about it looked wrong in review: a perfectly themed stylesheet nobody loads is the same as no stylesheet. A source scan now fails if any of the three shells renders these controls without loading it.

- **A spoken turn that produced no answer says so, instead of going quiet.** Filtering reasoning out of the stream can leave nothing behind, and an empty reply reaches the user as a chat log that skipped a turn and a speaker that stayed silent — indistinguishable from a microphone that never worked. The daemon now separates the two silences it can actually tell apart (tokens arrived and none survived the filter; no tokens arrived at all) and reports neither as an answer. The conversation stays open, because the next thing you say is a new turn — and so does the control that stops it: `active` was derived from the turn state alone, so one failed turn made the button offer "start" on a microphone that was already open, `start` returned early because the socket existed, and nothing left on screen could close it.

- **A voice conversation now leaves something on screen.** In VibeDesk the whole exchange — the question and the answer — happened with nothing written down anywhere: the composer mounted the duplex hook without an `onTurn`, so the chat log never heard about a spoken turn. Completed turns now land in the conversation as ordinary user and agent messages, so a session where half the questions were spoken still reads as one thread. And all three shells gain a live caption above the composer (`VoiceTranscript`): the sentence being spoken right now, under the question it answers. The two are deliberately different — the chat log gets a turn once, when it is complete; the caption covers the seconds in between, when previously a broken pipeline and a working one looked identical. The caption also outlives `active`, because the hook tears the conversation down on a failed start, which is exactly when there is something to explain.

- **The voice assistant no longer reads its own reasoning aloud.** Asked "how are you doing?", a reasoning model spoke two paragraphs of deliberation — *"The user says: Hey, how are you doing? As a voice assistant, respond in one or two short spoken sentences…"* — before giving the one-line answer. Ollama returns reasoning in a separate field and the provider splices it into the token stream as `<thinking>…</thinking>`; the voice path was the one consumer that never filtered it, so the sentence splitter cut the narration into sentences and spoke every one. The existing streaming filter now sits between the provider and the splitter. It has to be a state machine rather than a per-chunk strip: tokens are not tag-aligned, and `<thin` + `king>` arriving in different chunks both misses the tag and leaks its two halves into the speaker. `llm_ttft_ms` stays measured on the raw stream, so the gap to `first_audio_ms` on a reasoning model is visible rather than hidden — the model really was producing tokens that whole time.

- **The voice assistant can see the project you have open.** Asked about the workspace in the file tree beside it, it answered that it had no information about it — the typed chat path injected pinned memory, the context block, the open file and the file tree, and the voice path injected none of them. It was the one surface that never received the context every other path already had. The socket now carries a `set_context` control message, sent on connect and again whenever the workspace changes, folded into the turn's system prompt and bounded at 32k characters. An empty block *clears* it rather than leaving it unchanged: closing a project mid-conversation must not leave the assistant answering about the old one. The prompt asks it to say when the context does not say, rather than to be helpful about files it cannot see.
- **One spoken reply is one chat message.** A three-sentence answer arrived as three separate bubbles. `speaking` fires once per *sentence* because that is what drives streaming TTS — waiting for the whole reply would make first audio inherit the entire generation time — and the shared hook appended a message for each one. Sentences now extend the turn in progress and `reply` closes it with the model's own text, so the host's chat log hears about a turn once. The fold is a pure function (`reduceTurns`), so the property is unit-tested without a microphone, a socket or an AudioContext.

- **The git diff showed almost every line as added, whatever the change.** The "before" side was rebuilt in the frontend by walking the unified diff and keeping its `-` and context lines. A patch carries only the changed hunks; everything between them is not in it. Measured on a 500-line file with one line changed: the patch is 14 lines, the reconstruction yields 8, the file has 500 — so ~492 lines were reported as added. Both sides now come from git's object store, and a file that genuinely has no previous version is distinguished from a lookup that failed.
- **A file in the commit history diffed against the working tree, not against the commit.** Which usually meant no diff at all: while browsing history the working tree matches HEAD, so both sides came back identical and a commit looked like it had changed nothing. History entries now compare the commit against its first parent, and the viewer's header names the commit it is showing.
- **A long commit message no longer takes over the history list.** The whole message rendered, subject and body, so one commit with a real body pushed "Files Changed" and every file under it out of view. Clipped to the subject line or 100 characters, with `more` / `less` — and no toggle at all when nothing is hidden.
- **The voice buttons ignored the theme on every surface.** Their stylesheet named `--border`, `--surface`, `--fg`, `--muted` and `--accent-red`, none of which this design system defines, each with a GitHub-dark hex beside it. A `var()` fallback for a token that is never defined is not a fallback — the hex wins on every theme, forever. They now use the real tokens, and the full-duplex button matches `.panel-btn` in geometry as well as colour. Four of the dead names survived that pass in the duplex off-state and its × — the source-scan test caught them, and they are gone too.
- **A code comment rendered as text in the Review tab.** Moving the review section out of its collapsed wrapper carried the comment inside it into JSX children position, where `/* … */` is not a comment. Neither the type-checker nor the linter has anything to say about JSX text.
- **Editor hovers were clipped at the pane edge.** A TypeScript diagnostic came out cut mid-word — and because the text wraps to the hover's width *before* the clip, it read as a message that ends there rather than one that had been truncated. Monaco's overflow widgets now render in a layer that escapes the editor's `overflow: hidden`.
- **Chat got slower the longer a session ran, and slower again inside a single long reply.** Every streamed chunk re-rendered the entire transcript — re-parsing reasoning tags, tool markup and markdown for each message — and then re-parsed the growing reply on top of that. Measured with 30 messages and 20 chunks: 300 markdown renders where 0 were needed; and for a 40-chunk reply, 40 renders where 1 suffices.
- **A tool call whose markup was malformed no longer writes a garbage file.** The `path` attribute was read by searching for the first `">`, which is the *tag* terminator, not the attribute's. `<write_file path="src/main.rs" language="rust">` therefore yielded the path `src/main.rs" language="rust`, and a file was created with that literal name. Paths are now read to their own closing quote and checked before anything is written; a rejected tag is reported in the conversation rather than dropped.
- **The agent's recovery no longer reports itself as a crash.** The loop emits a circuit-breaker notice when it compacts context or hands a degrading run to a fresh agent, and then keeps going. VibeCoder treated every notice as terminal — printing "Agent halted", clearing the run's state — while the run carried on executing, so every tool call, approval prompt and the final answer after it were discarded.
- **Full-duplex voice failed to start on every desktop shell, and took push-to-talk down with it.** An `AudioWorklet` module is fetched under `script-src`, not `worker-src` — VibeCoder and VibeDesk ship `script-src 'self'` with `worker-src 'self' blob:`, so the capture module was rejected outright ("Not allowed by CSP", measured under the shipped policy). Fixed twice over: `script-src` now allows `blob:`, *and* capture falls back to a `ScriptProcessorNode` that fetches no module, so the feature no longer depends on a host's policy to work at all. Separately, a failed start released nothing — the microphone stayed open and push-to-talk could no longer acquire it, so one broken feature was disabling a working one. Teardown now runs on every failure path, and start failures name their remedy instead of saying "connection failed".
- **"No speech engine configured" on machines that had one.** The configured binary defaults to the bare name `whisper-server`, but was checked with `Path::exists()` — which asks whether it sits in the daemon's working directory. Bare names now resolve through `PATH`. The binary was also checked *before* the port, so an already-running server was ignored because of that failed check; the port is asked first now, since a listening server is usable whether or not a binary can be found to start another.
- **A voice turn you were still finishing is no longer discarded.** Barge-in treated "the user is talking while the assistant is speaking" and "the user is talking while the assistant is still thinking" as the same event. The second is someone finishing a thought — the 600 ms silence window ends a turn on a breath — so `"plus fifty one."` <pause> `"minus fifty four."` dropped the first half and answered `32 - 54` instead of `32 + 51 - 54`, with the transcript on screen, no reply, and no explanation. Words from a turn superseded before it spoke are now carried into the next turn; a turn superseded *while* speaking is still abandoned, because that is a real interruption.
- **`FEATURE-MATRIX` said VibeCoder had no parallel agents and no worktree isolation.** Both were wrong and had been for some time: AgentPanel's Parallel Mode calls `start_parallel_agent_task`, and WorktreePoolPanel calls `worktree_spawn` / `_list` / `_merge` / `_cleanup`. The rows now name the command they were checked against. Background agents stays ❌ — that panel issues no commands at all.

### Known issues

- **Microphone capture does not work on Linux**, for push-to-talk or duplex. WebKitGTK ships media capture off and denies the permission request unless the embedder answers it; `wry` implements that hook on macOS and Windows and skips Linux, and Tauri adds neither. The fix is two calls, reachable from Tauri's `with_webview()` — see `apply_linux_media_fix` in `tools/webview-probe`. Established from the dependency source; the CI job added here is its first real run.
- Full-duplex voice is **measured on macOS only**. Windows and Linux have the harness and a CI job but no numbers yet.

### Added — earlier in this cycle

- **DOCX, EPUB and Apple Pages open in the editor — and save back.** Word documents and e-books read as Markdown, Pages documents as plain text, editable in Monaco via **Edit text** in the viewer toolbar. Saving edits the original container in place rather than rebuilding it, so images, footnotes, stylesheets, metadata and page setup survive an edit that only changed a sentence. New: `crates/vibe-docfmt`, the `read_document_text` / `write_document_text` / `read_document_preview` commands, and [documents.md](/vibecody/documents/).
- **A save is only reported once it has been checked.** Every write is assembled in memory, re-read with the same reader the editor uses, and compared against the text that was saved; a mismatch is an error naming the first differing line, with the file left untouched. Structural edits a format cannot take — a new EPUB chapter, an added DOCX table row — are refused with an explanation instead of guessed at.
- **EPUBs are actually readable.** The viewer renders the book: its own stylesheets (scoped to the chapter and stripped of anything that could escape it), its images, its cover, a nested table of contents from the EPUB 3 navigation document or the EPUB 2 NCX, and links that work — a cross-reference moves to that chapter and scrolls to the anchor, while an external link opens in the browser instead of navigating the editor away. Reading moved to the backend (`epub_view.rs`), and two defects went with it: the browser-side ZIP reader's inflate function returned `null` unconditionally, so **every deflate-compressed chapter — which is every chapter of every real book — was dropped** and the viewer showed a card suggesting another application; and `href` was missing from the sanitiser's allow-list, so every link in every book rendered dead. ### Fixed

- **The code index persisted API keys in plaintext.** `EmbeddingProvider::OpenAI { api_key }` was `Serialize`, and the index was written as plain JSON — so every `.vibecli/index.json` built against a cloud provider contained that provider's key on disk. The index header now stores a model reference only; the embedder (and therefore the key) is supplied at runtime from the encrypted ProfileStore and is `#[serde(skip)]`. Pre-existing v1 indexes migrate automatically and the credential is dropped in the process, with a test asserting no `sk-` survives.

- **Changing embedding model silently returned nonsense instead of failing.** Three separate holes: the code index recorded no dimension or format version, so a mismatched model scored `0.0` against every chunk and looked empty rather than broken; `TurboQuantIndex::insert`'s dimension error was discarded at *both* call sites (`compressed_hnsw.rs`, `embeddings.rs`), so wrong-sized vectors were dropped without a word; and `vibe-memory`'s SQLite had no model or dimension column at all, so a `VIBE_MEMORY_DIM` change made every existing memory unreachable while the rows sat in the database. Indexes now carry a validated header, TurboQuant's error propagates, and each memory row records the model that embedded it — search compares only what it can compare and logs what it skipped.

- **VibeAIChat never started the VibeCLI daemon.** VibeCoder and VibeDesk both autostart it via the shared `daemon_bootstrap`; VibeAIChat had no spawn path whatsoever, and its manifest deliberately avoided the `vibecli` dependency. Since nearly every daemon route is behind `require_auth` and the bearer token only exists once a daemon has written it, launching VibeAIChat on its own produced a blanket 401 with nothing on screen explaining why. It now uses the same shared module — identity-checked `/health` reuse, binary resolution beyond bare `PATH`, poll-to-deadline for the ~16 s cold start, and four distinct failure states.

- **Stale bearer tokens produced a permanent 401 loop.** `vibecli serve` mints a fresh token on **every** start and all three shells autostart the daemon, so any token held across a restart is dead — and nothing invalidated it. VibeDesk retried on none of its 20 daemon calls, and `crates/vibe-desktop-voice` (linked into all three shells, so voice input broke everywhere at once) retried on neither of its two. Both now go through a `send_authed` helper that retries once with a token read straight from `~/.vibecli/daemon.token`, deliberately bypassing the explicit-token / `VIBECLI_TOKEN` precedence — that order is right for a first attempt and exactly wrong for a retry, since the stale value is usually why the request 401'd.

- **VibeCoder chat rendered markdown as raw text.** Assistant replies containing tables arrived as walls of `| --- |` rows and every emphasis as literal asterisks, while VibeDesk and VibeAIChat rendered the same reply correctly. Three causes stacked: `AIChat`'s `renderContent` extracted fenced code blocks and dumped all remaining prose into a `<pre>`; `remark-gfm` — which is what renders tables — was missing from VibeCoder's dependencies entirely; and neither the Vite alias table nor the tsconfig let the shared `Markdown` component resolve its imports. Chat now renders through the same component the other two shells use. Code blocks keep their Apply/copy affordances, and user messages stay literal.

- **Two phantom design tokens meant borders and buttons never rendered.** `var(--accent)` (22 uses across 11 panels) and `var(--border)` (74 uses, plus `--border-default` / `--border-secondary` / `--border-primary`) were referenced but defined nowhere; CSS drops an undefined `var()` declaration silently, so those backgrounds were transparent and those borders simply absent. Both now use the real `--accent-color` / `--border-color`, which are themed per-theme. Separately, `.panel-btn` declared no `background` and no `color`, so 43 buttons carrying no modifier class fell through to the browser's native `buttonface`/`buttontext` — light grey with black text on a dark panel, which is what made Configuration → Keys look unthemed. The base class is now themed, and all variants share one border box so buttons in a row line up. Three source-scan regression tests guard the lot, with the remaining undefined tokens recorded as an explicit, self-cleaning inventory.


- **JetBrains plugin and Neovim plugin sent no bearer token.** Nearly every daemon route is behind `require_auth`, so `/chat`, `/agent`, `/jobs` and the new voice routes were a silent 100% 401 from both — the JetBrains tool window's "Error" line and the Neovim "Daemon error" notice were that 401 every time. Both now resolve a token the same way every other client does (explicit config → `VIBECLI_TOKEN` → `VIBECLI_DAEMON_TOKEN` → `~/.vibecli/daemon.token`), and Neovim's SSE stream appends `?token=` since curl-as-argv can't carry a header there.

- **Goal-driven loops — `/loop goal <id-prefix>`.** Joined the two halves of autonomous execution: a `/goal` supplies the durable intent + `success_criteria`, `/loop` supplies the run-until-done engine. Parsing, prompt rendering, and hydration are pure and live in `loop_engine.rs` (`GoalBrief`, `hydrate_goal_loop`, `goal_loop_prompt`, `goal_validator_prompt`, `LoopSpec.goal_id` — `#[serde(default)]`, so pre-existing `loops.json` jobs still load); the store-touching edge (`resolve_goal_brief` / `goal_brief_by_id` / `link_goal_loop_start` / `record_goal_loop_outcome`) lives in `exec_goal_repl.rs` over a new `SessionStore::find_goal_by_prefix`.
  - **Stop condition is the criteria, not the model's opinion** — the worker prompt is explicitly told not to declare completion; a separate validator turn is shown the numbered criteria and answers `DONE` only if every one verifiably holds. A goal with no criteria still runs, with a warning that judgement falls back to the statement.
  - **Only confirmed success writes back** — `Done` flips the goal to `done`; max-iter, wall-clock expiry, Ctrl-C, and iteration errors leave the status untouched (an exhausted budget is not evidence of completion). Every outcome is attached to the goal as a link, so `/goal show` carries the history. Already-`done` goals are refused at start.
  - **Bounds + secrets** — `--max-iter N` and `--max-duration 45m` override the 20-iteration / 30-minute defaults (a mistyped bound errors rather than silently falling back); `--secret NAME` works as on any other loop.
  - **Machine-off parity** — `POST /v1/loops {"args":"goal <id>"}` hydrates server-side, and the daemon's hosted scheduler now runs a real done-validator: `LoopExecutor::run_iteration` takes a `validator: Option<&str>`, `scheduler_tick` takes a `validator_lookup` closure (criteria re-read each tick, so mid-run edits are honoured), and `ProviderLoopExecutor` asks the completion question in a separate turn. Recurring jobs skip the extra turn. Previously *no* hosted self-paced loop could ever signal done — it ran to its caps.

### Changed

- **The step budget now extends for a run that is still working, instead of cutting it off.** `max_steps` (default 50) is a runaway guard, but as a hard wall it also stopped healthy runs: an agent executing its plan tool-call by tool-call hit the limit mid-plan, reported `Partial`, and left the user to press Resume to finish work that was going fine. `AgentLoop` now grants up to `max_step_extensions` (default 3) further budgets of `max_steps` each — a ceiling of `max_steps * (1 + N)`, 200 steps by default.
  - **An extension is earned, not automatic.** The decision is a pure `should_extend_budget(extensions_used, max_extensions, health, steps_since_progress)`, and every guard vetoes independently: extensions must remain, the circuit breaker must read `Progress` (not `Stalled` / `Spinning` / `Degraded` / `Blocked`), and a **successful** tool call must have landed within the last 10 steps. Failed tool calls deliberately do not count as progress — an agent retrying the same broken command is precisely what the budget exists to stop.
  - `AgentLoop::with_step_extensions(0)` restores the old hard wall; a test pins that.
  - Mechanically, the loop advances `step` at the *top* of its body rather than the bottom. The body has many `continue`s, and a bottom increment would skip every one of them and spin forever. The post-loop `Partial` reporting now quotes the effective budget rather than `max_steps`, so it no longer understates how far the run got.
  - 5 new tests: the policy's veto cases, the bound, a productive run that overruns a 2-step budget and now **completes** where it previously reported `Partial`, `with_step_extensions(0)` restoring the wall, and an agent whose every tool call fails not being extended.
  - **Tunable per run** — `POST /agent` takes an optional `max_step_extensions`, so an operator can trade completion against cost without a rebuild (`0` = hard wall). Absent means the harness default, so no existing client changes behaviour. `max_steps == 0` is honoured rather than extended.
  - **Sub-agents get 1 extension, not 3.** The multiplier compounds down the tree: at the root default a depth-2 nest would let every sub-agent run 4× its budget, and a parent spawning many of them multiplies that again. 2× absorbs an overrun without the fan-out.

### Fixed

- **A chat history containing one huge message wedged the run permanently.** `prune_messages` only ever dropped the *middle* of the conversation. When the oversize lived in a message it must preserve — the system prompt, or a `read_file` / `bash` result in the six-message tail — pruning was a no-op, so every following step re-sent the identical too-large payload and the provider rejected it the same way each time. A test reproduced it at **100,120 tokens against a 10,000 budget**. Pruning now falls through to clipping individual messages (largest first, both ends kept around a `…[truncated to fit the context window]…` marker, always on UTF-8 char boundaries) so the next request actually fits. Message count and order are preserved — dropping the system prompt or the newest tool result breaks the loop worse than eliding the middle of one payload. Best-effort by construction: `estimate_tokens` charges 8 tokens of framing per message, so a budget under `8 × len` cannot be met by clipping, and the helper degrades rather than spinning (pinned by a test).

- **Subprocess dispatch had the original `/agent` bug, untouched.** The child loop in `main.rs` matched four `AgentEvent` variants and swallowed the rest with `_ => continue` — so a dispatched run that stopped mid-plan drained the channel, left `completed` false, and the fallback sent `DispatchFrame::Complete { "Agent finished." }`, which the parent records as `JobStatus::Complete`. Byte-for-byte the defect fixed in `serve.rs` on the first pass, in a code path never opened. `ToolCallPending` was dropped there too, silently abandoning the run. Found by verifying a claim ("the remaining catch-alls are already audited") instead of restating it — two `AgentEvent` matches in `main.rs` had never been read.
  - `DispatchFrame` gains a `Partial` variant, since `Complete` is defined by this protocol as *success* and `Error` overstates a resumable run. The parent publishes the rich `partial` event to SSE and marks `JobStatus::Partial`. Safe to add a variant: the child is this same binary, self-spawned via `current_exe()`, so parent and child can never be different versions.
  - A second `main.rs` loop (console output) also dropped `Partial`, printing nothing at all when a run ended — the tool steps then silence.

- **kodegraph community detection was seeded by hash order, making the workspace suite intermittently red.** Label propagation resolved ties with `tally.into_iter().max_by_key(|(_, c)| *c)`. `HashMap` iteration order is randomly seeded per process and `max_by_key` returns the *last* maximum, so which label won a tie varied run to run and the same graph settled differently — `detects_a_community_from_a_cluster` failed roughly one run in ten. Two further orderings had the same flaw: communities were grouped out of a `HashMap` and sorted with a *stable* sort on size alone, so equal-sized communities kept their hash order, and member lists were unsorted. Ties now break on the label id, the sort is total (size, then id), and members are sorted — the result is a function of the graph alone. A new test asserts the a/b/c triangle groups together and that 25 rebuilds produce byte-identical ids, members and ordering. Found by finally running `cargo test --workspace` rather than `--lib`; unrelated to the rest of this changelog entry, and pre-existing.

- **The CLI's `spawn_agent` had the same unfinished-subtask bug as VibeCoder's, verbatim.** `tool_executor.rs` and `vibecoder/src-tauri/agent_executor.rs` carry duplicate copies of the sub-agent event loop; fixing one left the other reporting "Sub-agent completed." for a sub-agent that stopped mid-plan, and silently abandoning the run when a policy gated a tool. Both copies now match. Found by auditing catch-all match arms rather than by review.

- **Flutter's watch poller never saw a `partial` or `cancelled` session as finished.** `watch_sync_service.dart` tested `status == 'complete' || status == 'failed'`, an allow-list of two — so `cancelled` (pre-existing) and `partial` (once the daemon gained it) spun the full 60-second timeout and then returned `[]`, discarding assistant messages already fetched and leaving the phone blank. Terminal is now "not running/queued", and a timeout hands back whatever did arrive.

- **Wear OS read an HTTP failure on either SSE stream as a clean end.** OkHttp calls `EventSourceListener.onFailure` with a **null** throwable when the failure *is* an unsuccessful HTTP response, and both `openStream` and `openTaintedPendingStream` did `if (t != null) onError(t) else onComplete()`. So a 401 or 500 ran the completion path: `ConversationScreen` cleared the partial reply and dropped the spinner with no error shown. On the tainted-prompt stream it is worse — the wrist shows no pending approvals while a run sits blocked waiting for one. Both now distinguish an unsuccessful response from a genuine close.

- **A JetBrains `step` with no `success` field rendered as "ok".** Introduced by this changelog's own parser rewrite, and caught by the follow-up sweep rather than by review. `AgentEvent.Step.success` is now `Boolean?` and renders `outcome not reported` when the daemon said nothing.

- **An unverified observe-act step erased the failure streak, so a failing loop never bailed out.** `ObserveActSession::record_step` computed success as `verification_result.map(|v| v.success).unwrap_or(true)` — the comment said `// No verification = assume success` — and a "success" resets `consecutive_failures` to 0. With unverified steps interleaved (the normal case when `verify_after_action` is off, or verification itself fails), the streak could never reach `max_consecutive_failures`, so a loop that was failing every step ran the entire `max_steps` budget instead of aborting after three. Absent verification is now neither success nor failure: the streak is left unchanged. Three tests, including one that drives failure/unverified pairs and asserts the loop stops rather than running to the cap.

- **A `tool_end` with no `success` field showed a green tick on the wrist.** `to_watch_event_json` defaulted the missing field to `true` and reported `status: "ok"`. `status` is `Option<String>` precisely so absence can stay absent; it is now `None` when the producer said nothing.

- **A failed watch/phone reply was recorded in the database as a completed one.** The `/watch/dispatch` streaming task matched chunks with `if let Ok(text) = chunk`, so a mid-stream provider error was **silently discarded** and the loop carried on. The trailing `{"type":"done","status":"complete"}` still fired, and — uniquely on this path — `finish_session(…, "complete")` plus the truncated assistant message were **persisted**. The wrist showed a half-answer as finished and the transcript agreed with it from then on. A failed stream is now terminal: it emits `error`, stores `failed` with the provider's message, and keeps the tokens that did arrive (the user watched them stream in) without ever recording them as a completion. The persistence decision is extracted into `persist_watch_turn` and pinned by three tests (failed-with-partial, clean, failed-before-any-output).

- **`/chat` and `/chat/stream` ignored the model you picked.** `AGENTS.md`'s provider-agnostic rule says daemon routes read provider/model from the request body, not the daemon's startup config, and `POST /agent` already did. The chat routes did not: `ChatRequest.model` rode the wire but was marked `#[allow(dead_code)]` and never read, and there was no `provider` field at all. A user who chose a model in the toolbar was answered by whatever the daemon happened to boot with — silently, and differently from the agent route on the same screen. Both routes now resolve through a shared `chat_provider_for`, which honours `provider` + `model` together (matching `/agent`), wraps the result in `resilient()` since a chat turn has no retry loop of its own, and falls back to the daemon provider when the override is absent or unbuildable — so existing callers are unaffected. Pinned by tests covering both-present, either-alone, empty-string, unknown-provider, and the identity that surfaces through the wrapper.

- **`/chat/stream` reported a failed reply as a finished one.** A mid-stream provider error emitted an `error` event and then *carried on*, so the trailing `done` still fired: clients saw `error` followed by `done` and rendered a truncated reply as complete. `error` is now terminal.

- **A dropped connection reported a still-running task as finished.** VibeDesk settled a stream that closed while `running` straight to `done`, on the assumption that it meant "the run ended without a terminal event". That assumption stopped holding once the daemon began always emitting a terminal event: reaching that path now means the *transport* dropped — a network blip, a daemon restart, the laptop sleeping — while the agent carried on working. The chat said the task was done, the transcript stopped mid-stream, and the task card was PATCHed to `reviewing`.
  - The daemon is authoritative and already had the pieces: `GET /jobs/:id` for real status and a durable event log replayable from seq 0. A closed stream now **reconciles** — if the job is genuinely terminal it settles to *that* outcome (`failed` → error, `cancelled`, `partial`, else done); if it is still running it reattaches and replays, so nothing streamed before the drop is lost. Bounded at 5 consecutive attempts, after which the run is reported as lost rather than reconnecting forever, and the allowance resets on every real terminal event.
  - A user-requested cancel still short-circuits to `cancelled` before any of this.

- **Choosing a model in the toolbar silently disabled retry.** The daemon's default provider is wrapped in `ResilientProvider` by `main.rs::create_provider`, but `build_provider_override_with_effort` — used whenever a request carries `provider` + `model`, which VibeDesk's model picker, mobile, watch and the IDE clients all send — returned a **raw** provider. Every one-shot LLM call with no retry loop of its own (`/chat`, chat-mode agent turns, the planner, recap synthesis) therefore died on a single transient 503, and only for users who had picked a model. Those call sites now wrap explicitly via a new `resilient()` helper.
  - The builder deliberately still returns raw: `AgentLoop` retries `stream_chat` itself, so wrapping there would nest two backoff loops (4 × 5 = 20 attempts) and stall a run for minutes on a hard outage. A test pins that the builder is unwrapped and that `resilient()` is identity-preserving (`name()` delegates), so wrapping never changes which model a caller believes it is talking to.

- **Unfinished agent runs were reported to every remote client as successes.** `AgentEvent` has nine variants; the daemon's `/agent` → `/stream/{id}` route matched four and swallowed the rest with `_ => continue`. `AgentEvent::Partial` — the event the harness emits when the agent exhausts its step budget or stops mid-plan — was one of the swallowed ones, so the loop drained with no terminal event and the "clients must not hang" fallback published `complete("Agent finished.")` and marked the job `Complete`. The real partial summary and the list of plan items that were never executed were discarded. Every client behind the daemon (mobile, watch, VS Code, JetBrains, Neovim, Agent SDK, VibeDesk) was told the task had finished.
  - **`ToolCallPending` was swallowed the same way, which killed the run outright.** Dropping `result_tx` without answering made `AgentLoop::run` hit `Err(_) => return Ok(())` — the one path in the harness that ended a run with *no* terminal event at all — and the same fallback then reported that abandoned run as a success. Reachable from any caller passing `approval: "suggest"`/`"autoedit"`, which the route accepts.
  - **Harness** — that silent `return Ok(())` now emits `AgentEvent::Error` naming the tool and the dropped channel. A new `assert_terminal_event` test pins the contract across five paths: **every run ends with exactly one of `Complete` / `Partial` / `Error`.** Callers that infer success from "no `Error` seen" are now safe by construction.
  - **Wire protocol** — two new SSE kinds. `partial` is terminal and carries `steps_completed` / `steps_planned` / `remaining_plan`; `retry` is non-terminal and carries `attempt` / `max_attempts` / `backoff_ms` (previously a retrying agent was indistinguishable from a hung one for up to 60 s per attempt). `system` now also carries circuit-breaker and verifier notices. New `AgentEventPayload` fields are `Option` + `skip_serializing_if`, so the existing kinds' wire shape is byte-identical and old rows in the durable event log still deserialize — both pinned by tests.
  - **`JobStatus::Partial`** — terminal, but neither `Complete` nor `Failed`: the work done is real and the run is resumable. Folding it into `Complete` is what let unfinished tasks read as successes.
  - **Client fan-out** — Agent SDK + VS Code (`isTerminalAgentEvent`, replacing four hand-rolled `complete || error` checks), VibeDesk (`stream_agent` forwards `partial`/`retry`; `RunState` gains `partial`, rendered as "incomplete" and now **offering Retry**, which it previously withheld on exactly the runs that needed it; the replay path no longer drops the partial notice, so a reopened chat still shows the work was unfinished), VibeCoder `BackgroundJobsPanel` (closes the `EventSource` on `partial` instead of leaking it until the browser errors out), and Neovim.
  - **JetBrains agent window rendered nothing at all** — pre-existing and unrelated to the above. Its `parseEvent` looked for `thinking` / `text` / `tool_call` / `tool_result` and read `summary` / `message` / `text`: kinds and fields the daemon has never emitted. Every streamed token fell through to `null` and `complete` rendered an empty summary. Rebuilt against the real `AgentEventPayload` shape, with `Step` / `System` / `Retry` / `Partial` added.
  - **Sub-agents** — `spawn_agent` (`vibecoder/src-tauri/agent_executor.rs`) dropped `Partial` into `_ => {}`, leaving `summary` empty, which its tail rendered as "Sub-agent completed." to the *parent agent*. A sub-agent that ran out of steps mid-plan now returns `ToolResult::err` with what it finished and what it did not, so the parent re-dispatches instead of building on unfinished work.
  - Docs: `docs/api-reference.md` gains a terminal/non-terminal event table, the partial-run example, and the `partial` job status.

- **VibeDesk · Sandbox mode with per-axis permissions.** The agent is normally jailed to `workspace_root` — `ToolExecutor::resolve_safe` canonicalizes every path and rejects escapes. Sandbox mode relaxes that jail, which is the only place in the product where a model gets reach beyond the project it was pointed at, so the relaxation is explicit, per-axis, and denies by default. New `sandbox_policy.rs` (`read_outside` · `write_outside` · `exec_outside` · `network`, plus `allow_roots` / `deny_roots`), a `sandbox` field on `POST /agent`, and a composer settings sheet in VibeDesk.
  - **Credentials are unreachable by construction.** `vibe_core::path_guard` (`~/.ssh`, `~/.aws`, `~/.vibecli`, `id_rsa`, `daemon.token`, …) is applied to every outside path *before* any grant is consulted, so no combination of toggles — including an `allow_root` pointing straight at `~/.ssh` — reaches a key. Pinned by `credentials_are_never_reachable_however_configured`, which asserts it under a maximally permissive policy.
  - **Deny beats allow; grants only apply in the mode that asked for them.** `deny_roots` is checked before `allow_roots`. `effective_sandbox_policy()` is extracted and tested precisely so a `sandbox` field left on an Agent request cannot silently widen an ordinary run — the obvious way this feature could have leaked.
  - **Inside the workspace is untouched.** The policy is consulted only for paths that escape the jail, so enabling sandbox mode can only add reach, never remove it. Deliberately, the credential deny-list is *not* applied inward: `DENIED_FILENAMES` includes `config.json`, an ordinary project file.
  - **Sub-agents inherit the policy.** `spawn_agent` builds a child executor field by field; omitting `sandbox_policy` there would have handed the child a locked default, so a sandbox run's sub-agent would fail on the very paths its parent was granted.
  - **`exec_outside` enforces something real.** `bash` is not path-jailed — the shell reaches whatever the OS allows, in Agent mode too — so a "commands may not leave the workspace" path check would have been theatre. The axis instead drives `ToolExecutor`'s existing OS-level confinement (bwrap+Landlock / sandbox-exec / AppContainer): off confines commands, on runs them as they do today. An earlier draft shipped a `allows_exec_in()` guard that could never fire; it was removed rather than left as a setting that enforces nothing.
  - **Verified** — 9 policy tests, 3 executor tests proving the jail widens for the granted axis only, 4 request-plumbing tests, and a live run: sandbox mode with no grants refused to read a canary file outside the workspace and reported the jail message. 12,926 vibecli tests green.

The agent's system prompt orders it to reply *only* with a tool call, so asking a plain question in Agent mode got an answer shaped like work — Chat mode is how you ask without starting a task. When stripping leaves nothing, the chat path now unwraps the tags and keeps the text. - **`</mm:think>` rendered verbatim in chat, mid-sentence.** minimax-m3 emits a **namespaced** reasoning tag, and all three strippers matched only `think|thinking` — so `<mm:think>` sailed through every one. - **The tool parser now accepts three dialects, not one.** `parse_tool_calls` understood only `<tool_call name="…">`, so a model that reached for any other shape produced a turn that looked like prose and did nothing.
  - **Element style** — `<write_file path="a.py">body</write_file>`, `<read_file path="x"/>`. This is the format **VibeCoder's own chat prompt teaches** (`vibecoder/src-tauri/src/commands.rs`), so models carry it into agent runs where nothing parsed it.

Common aliases (`file_path`/`file` → `path`, `cmd` → `command`) are normalised, and element bodies map to each tool's natural parameter (`write_file` → `content`, `bash` → `command`, …).

- **Every client 401'd against a healthy daemon — one cascade, three causes.** Reported as three unrelated symptoms (VibeAIChat 401, VibeDesk "Couldn't load chats", VibeCoder "Port 7878 is in use by another program"). All one chain: `/health` shared the public routes' **10-req/min per-IP bucket**, and three desktop apps plus `daemon_bootstrap::probe`'s 250ms startup poll all arrive from `127.0.0.1` — so the bucket was exhausted in seconds and never recovered. A throttled `/health` returns `{"error":"Rate limit exceeded"}`, which carries no `service` field, so `probe()` read a healthy daemon as a foreign process; clients then spawned replacement daemons, and each replacement **wrote `~/.vibecli/daemon.token` before binding**, so the loser clobbered the live daemon's token on its way out. Confirmed on the machine: daemon started 19:45:32, token file rewritten 20:00:40 by a process that never held the port.
  - **`/health` is off the shared bucket** (`serve.rs`) with its own 600/min floodgate — bounded against a runaway client, unreachable by honest polling. Throttling the one route every client polls for liveness *and identity* is self-defeating: the failure is not a slow health check, it is the cascade above.
  - **Bind precedes the token write.** Binding reserves the port, so a daemon that cannot have it now fails before touching the shared token file. - **Daemon autostart failed in every Finder-launched app — "exited immediately (exit status: 1)".** The daemon derives its workspace root, and therefore `<workspace>/.vibecli/`, from its working directory. The daemon then tried to create `/.vibecli/` on the read-only system volume and died before binding: `Error: rl run store: storage: Read-only file system (os error 30)`. Launching from a terminal always worked, because a shell's cwd is writable — which is why this survived so long.

- **Editor IntelliSense — completion, hover, go-to-definition, signature help and diagnostics work again.** Five independent defects, each sufficient on its own to make every LSP request return nothing. Verified against real servers, not just fixtures: `rust-analyzer` now returns 165 completions for `text.` on text that exists only in the editor, and `clangd` returns exactly the struct's fields.
  - **The message pump deadlocked the connection.** The client forwarded every inbound message into a 32-slot `mpsc` that only an in-flight request drained. `rust-analyzer` emits thousands of `$/progress` notifications while indexing, so the reader wedged on the full channel, stopped draining the server's stdout, the pipe filled, and the server blocked on write — IntelliSense died seconds after opening a file and never recovered. `client.rs` is now a dispatcher: a reader task routes responses through a pending-request map (so concurrent requests can't consume each other's replies — hover could previously return a completion list), stores `publishDiagnostics`, and **answers server→client requests** (`workspace/configuration`, `client/registerCapability`, `window/workDoneProgress/create`, …) instead of dropping them, which is what a server waits on forever. Every request has a timeout, and a server that exits fails its in-flight requests immediately rather than making each wait out the timeout. Framing now scans headers to the blank line (servers that send `Content-Type` used to desynchronise the stream permanently).
  - **Every document URI was one no server had heard of.** `<Editor>` had no `path` prop, so all files shared a single model at `inmemory://model/1`, while `didOpen` announced `file://…`. As a side effect Monaco's own TypeScript service can finally resolve imports *across* open files.
  - **Edits were never sent.** `lsp_did_change` had no caller, so servers answered against the text as it was when the file opened — nothing you typed could be completed. Edits are now pushed (debounced 250 ms, and always flushed before a completion/hover/definition request so a request can't race its own edit), on AI-applied diffs and undo too. Versions are owned by the client and increase monotonically; a change to a document the server never saw self-heals into a `didOpen`.
  - **Completion kinds and snippets were mistranslated.** LSP and Monaco both call the enum `CompletionItemKind` and agree on no value (LSP `Text` is 1; Monaco's is 18, `Method` is 0), so every suggestion carried a wrong icon; mapping is now by name, since Monaco renumbers (`Snippet` is 28 in 0.55, was 27). `insertTextFormat: 2` now sets `InsertAsSnippet` instead of typing `${1:arg}` literally. Auto-import edits, commit characters, `sortText`/`filterText`/`preselect`, deprecation tags, `labelDetails` and `completionItem/resolve` documentation are all carried through.
  - **No trigger characters were registered**, so `foo.` and `Vec::` showed nothing while mid-identifier completion appeared to work. They now come from the server's own capabilities (multi-character triggers split into the single characters Monaco accepts).
  - **`ClientCapabilities::default()` declared nothing** — an empty object is how you get a server that answers with plain labels, no snippets and no docs, or refuses outright. We now declare completion (snippets, resolve, all 25 kinds), hover/signature-help markdown, synchronization with `didSave`, `publishDiagnostics`, and workspace folders.
  - **Servers are found where they are installed.** A Finder-launched app inherits launchd's bare `PATH`, which contains no `~/.cargo/bin`, Homebrew prefix or npm global — so `rust-analyzer` was `No such file or directory` in the bundled `.app` even when it worked in `cargo run`. Availability is a directory scan, not ~60 `which` subprocesses.

Clients are handed out as `Arc`, so the manager lock is released before awaiting: one cold `rust-analyzer` no longer stalls hover in every other language. Dead clients are replaced, not reused.

Declarative surface for swapping attention KV-storage strategies: `Fp16 | Fp8 | Int8 | TurboQuant | Custom(name)`. No runtime effect yet; the actual KV-cache kernel work lands in Phase 3 as a `mistralrs-quant` contribution.
- **Phase 3 KV-cache TurboQuant spike (`vibe-infer::kv_cache_tq` + `examples/kv_cache_bench`)** — pure-Rust PolarQuant+QJL prototype over `[num_heads, seq_len, head_dim]` tensors, with a bench that compares against simulated Fp8 (E4M3) and symmetric Int8. Run with `cargo run -p vibe-infer --release --example kv_cache_bench [num_heads seq_len head_dim]`. **Findings at head_dim=128 against realistic spiked-attention data:** 4.57× memory savings vs fp16 (measured 0.4375 B/el — the theoretical ≥5× asymptotic is not reached at typical head_dim because the per-vector 8 B scalar overhead (radius + residual_norm) amortises to +0.0625 B/el), mean reconstructed-K cosine 0.92, softmax attention MAE 0.0000 (below printable precision), and **100% top-1 attention-argmax agreement** with fp16 — zero misrouted tokens. The `KvCacheMethod::TurboQuant.bytes_per_element()` estimate is updated 0.375 → 0.4375 to reflect the real number; downstream pod-sizing numbers follow. Spike conclusion: viable for a `mistralrs-quant` kernel PR — TurboQuant delivers 2.3× more compression than Fp8 without costing attention quality on realistic distributions.
